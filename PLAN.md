> - **Сначала фронтенд без бэкенда** — доводим удобный вид/UX на моковых данных, бэкенд (Go + SQLite) прикручиваем в конце.

> - **UX-решения (фазы 0–1):** вид календаря по умолчанию на десктопе — **Неделя** (на мобильном — День); создание задач — **quick-add строка + drawer с полной формой**; темы — **светлая + тёмная с переключателем** (Tailwind class strategy); поля формы задачи — **минимум**: название, естимейт (ч), дедлайн, приоритет, сфера (описание — опционально через «ещё»).
> - **UX-решения (допилка фаз 0–1, 23.08):** задача = **полоска от startDate до deadline** (гант-стиль в видах Неделя/Месяц, дорожки через жадную раскладку `assignLanes`); **у каждой задачи свой цвет полоски** (контрастная палитра из 10 цветов по хэшу id, `taskColor()`), точка на полоске = сфера, ❗/🔥 = высокий/критический приоритет; у задачи есть поле **Старт (startDate), по умолчанию = сегодня**; задача без дедлайна — однодневная полоска на дату старта. **Выполненные задачи остаются на дашборде** зачёркнутыми (статус-фильтр по умолчанию: todo+in_progress+done; отменённые скрыты). **Прошлое ограничено** стартом самой ранней неотменённой задачи (кнопка «←» дальше не ведёт). Семантика полоски = «окно выполнения», распределение часов по дням появится в фазе 3. Ключ localStorage: `todolist.v2`.

## 1. Обзор продукта

Классический todolist с «умным планированием»:

- Задачи: название, описание, **естимейт в часах** (напр. 5ч), дедлайн, важность (priority), сфера (category: работа / учёба / быт), статус.
- Дашборд-календарь с видами **День / Неделя / Месяц** (вкладки) + фильтры по статусу, приоритету, сфере.
- Рабочие окна (в какие часы я работаю над делами) и дневная ёмкость (сколько часов в день готов уделять делам).
- «Размазывание» естимейта: задача 5ч с дедлайном через 2 недели раскладывается по дням с учётом ёмкости и важности.
- Встроенный Pomodoro-таймер, привязанный к задаче.
- Помощник по срокам: rule-based движок, интерфейс допускает LLM позже.

Адаптивная вёрстка (mobile-first, desktop-полноценный).

## 2. Технологический стек

### Frontend (реализуется первым, самостоятельно)
- **React 18 + TypeScript + Vite**
- Роутинг: `react-router-dom`
- Server-state/data-кэш: `@tanstack/react-query` — работает и поверх локального репозитория, переезд на HTTP потом безболезненный.
- Формы: `react-hook-form` + `zod`.
- Стили: **Tailwind CSS**, mobile-first.
- Дата/время: `date-fns`, локаль `ru`.
- Календарь: **своя реализация** на CSS Grid (день/неделя/месяц). DnD между днями — `@dnd-kit/core` (опционально, поздняя фаза).
- Состояние вида/фильтров: **URL search params** (шарибельные ссылки).
- Dev-сервер: `npm run dev`, без прокси до появления бэкенда.

### Слой данных на время «без бэкенда»
Абстракция репозитория, чтобы подменить реализацию при подключении Go:

```ts
// src/data/types.ts — доменные типы и enum'ы
// src/data/repository.ts — интерфейс Repository (tasks, settings, slices, pomodoro)
// src/data/local/localRepository.ts — реализация на localStorage + seed-данные
// src/data/http/httpRepository.ts — HTTP-реализация (появится в фазе с бэкендом)
```

- Хранение: `localStorage` (ключ `todolist.v1`), версионирование схемы + миграция при изменении.
- Seed-набор демо-задач при первом запуске (можно сбросить в настройках).
- react-query поверх репозитория: ключи `['tasks']`, `['calendar']`, `['settings']` и т.д.; мутации инвалидируют ключи. При переходе на HTTP меняется **только** фабрика репозитория.

### Backend (последняя фаза)
- **Go 1.22+**, роутер `chi`, SQLite-драйвер **`modernc.org/sqlite`** (pure Go, без cgo).
- Embedded-миграции (`embed` + `migrations/*.sql`, таблица `schema_migrations`).
- Слои: `httpapi → service → repository`. Конфиг через env (`TODO_DB_PATH`, `TODO_PORT=8080`).
- CORS allow `http://localhost:5173`, прокси `/api` в vite.config.

## 3. Модель данных

Единицы времени в UI — **часы** (number, шаг 0.5). Внутри хранилища — тоже часы (REAL), чтобы не плодить конверсии. Даты — ISO `YYYY-MM-DD`, timestamp — RFC3339.

```ts
type TaskStatus = 'todo' | 'in_progress' | 'done' | 'cancelled';
type Category = 'work' | 'study' | 'life';
// priority: 1=low 2=medium 3=high 4=critical

interface Task {
  id: string;                 // uuid
  title: string;
  description?: string;
  status: TaskStatus;
  priority: 1|2|3|4;
  category: Category;
  estimateHours?: number;     // общий естимейт, часы
  remainingHours?: number;    // остаток для планировщика
  deadline?: string;          // YYYY-MM-DD
  startDate?: string;         // не раньше какого дня планировать
  createdAt: string; updatedAt: string; doneAt?: string;
}

interface WorkWindow { id: string; weekday: 0|1|2|3|4|5|6; startMin: number; endMin: number; } // минуты от полуночи
interface DayCapacity { date: string; capacityHours: number; }   // переопределение на день
interface Settings { defaultDailyCapacityHours: number; pomodoroWorkMin: number; pomodoroBreakMin: number; }

interface TaskSlice {           // результат размазывания
  id: string; taskId: string; date: string;   // unique(taskId, date)
  plannedHours: number; doneHours: number;
}

interface PomodoroSession {
  id: string; taskId?: string; startedAt: string; endedAt?: string;
  kind: 'work'|'break'; plannedMin: number; actualMin?: number;
}
```

## 4. Фронт: страницы и UX

- **`/` — Dashboard (календарь).** Вкладки `День | Неделя | Месяц` + фильтры-чипы (статус, приоритет, сфера). Состояние в URL (`?view=week&date=2026-08-23&priority=3,4`). Десктоп по умолчанию — **Неделя**, мобильный (<640px) — **День**.
  - **Неделя/Месяц:** задачи — полоски (бары) от старта до дедлайна, раскладываются по дорожкам; «‹/›» — полоска продолжается за пределами видимого диапазона; цвет = приоритет, точка = сфера.
  - **День:** таймлайн по рабочему окну + список задач дня, прогресс-бар ёмкости («запланировано 3ч из 4ч»).
  - Клик по задаче → drawer: детали, быстрые действия (done, запустить помидоро, размазать).
- **`/tasks` — все задачи:** карточки/таблица, группировка по статусу.
- **`/settings` — рабочие окна по дням недели, дефолтная ёмкость (часы/день), настройки помидоро, сброс seed-данных.**
- **Создание задач:** quick-add строка (название + Enter → задача с дефолтами) + drawer с полной формой (минимум полей: название, естимейт ч, старт, дедлайн, приоритет, сфера; описание — под спойлером «ещё»). Кнопки **«Размазать»** (планировщик) и **«Подскажи срок»** (помощник) в drawer-форме.
- **Тема:** светлая + тёмная, переключатель в шапке, Tailwind `darkMode: 'class'`, выбор в localStorage + `prefers-color-scheme` как дефолт.
- **Pomodoro-виджет** — плавающий 🍅 с любой страницы: выбор задачи, таймер work/break, авто-перерыв, списание часов в задачу/срез, статистика «фокус сегодня».
- **Адаптив:** <640px — вид «День» по умолчанию, фильтры в bottom-sheet; ≥1024px — полноценный месяц.

## 5. Алгоритм размазывания (`web/src/domain/planner.ts`)

Вход: задача (estimate/remaining, deadline, priority, startDate), рабочие окна, ёмкости дней, существующие срезы.

1. Окно планирования: `[max(today, startDate) .. deadline]` (без дедлайна — ближайшие 14 дней).
2. По каждому дню: `free = capacity(date) − sum(planned срезов дня)`; день без рабочего окна (weekday) = выходной, пропускаем. capacity = DayCapacity или default из Settings. **Задачи категории `work` размазываются только на будни (сб/вс пропускаются всегда); `study`/`life` — можно и в выходные, если там есть окно.** Округление часов — вверх до 0.5ч.
3. Распределение: `dailyShare = min(free, ceil(remaining / daysLeft))`, стратегии `even|front|back` (дефолт `even`); округление до 0.5ч.
4. Не хватает ёмкости → `overflowHours` + предложение (поднять ёмкость дней / сдвинуть дедлайн). Молча сверх ёмкости не планируем.
5. `replan`: активные задачи сортируются `(priority desc, deadline asc)`, будущие срезы чистятся, перекладываем жадно. **Задачи с ручными срезами (`manual=true` — план правили в панели «Размазать») replan не трогает** — их план сохраняется, остальные задачи планируются вокруг них. Округление часов — вверх до 0.5ч.

Помощник по срокам использует тот же планировщик: предлагает дедлайн = первый день, где разбивка сходится без overflow и с запасом ~20%. Интерфейс `DeadlineAdvisor` — позже LLM-реализация.

- **Фаза 4 — Pomodoro.** Таймер (work/break, звук), привязка к задаче, списание часов в срез/задачу, статистика. DoD: помидор уменьшает remaining и увеличивает doneHours среза.

## 8. Правила кодинга (договорённости)

- Одна фича = один логический кусок; **git-мутации только по явной просьбе пользователя**.
- Фронт: работа с данными только через `src/data/` (интерфейс Repository) + react-query; бизнес-логика — чистые функции в `src/domain/` с unit-тестами (vitest).
- Естимейты везде в часах (шаг 0.5), enum'ы и типы — только из `src/data/types.ts`.
- Минимум зависимостей, Tailwind без тяжёлых UI-фреймворков.
- Завершение фазы: `npm run build`, `tsc --noEmit`, `vitest run` (где есть тесты), ручной смоук по DoD фазы. В фазе 7 добавляется `go test ./...`.
- При изменении договорённостей — обновлять `PLAN.md` в корне проекта.
